# i18n Rules

This project treats language output as a rendering concern. Evidence IDs,
source IDs, claim IDs, URLs, hashes, and report-set structure are language
neutral. Human-facing Markdown and prompt text may be localized.

## Required Output Languages

For reusable research reports, the default output languages are:

- `zh-TW`
- `en`

The canonical report JSON stores stable evidence and optional
`localized_content`. Markdown renderers produce:

- `<report_set_id>.zh-TW.md`
- `<report_set_id>.en.md`

## Chinese Style

Chinese output must follow these rules:

- Use Traditional Chinese for explanation, analysis, limitations, and
  recommendations.
- Preserve technical proper nouns in their source form, for example `A2A`,
  `MCP`, `OpenAI Agents SDK`, `LangGraph`, `Conftest`, `OPA/Rego`, `GitHub`,
  `SWE-bench`.
- Do not translate identifiers, file paths, commands, schema fields, source
  IDs, claim IDs, hashes, URLs, or package names.
- When a translated explanation introduces a term, prefer:
  `原文專有名詞（中文解釋）`.
- Do not mix garbled encodings. Files must be written as UTF-8.

## Agent Rules

- Agents must not hard-code Chinese labels into canonical JSON evidence fields.
- Agents may localize Markdown headings and prose.
- A translated report must not change evidence mapping, claim IDs, source IDs,
  resolution IDs, quality scores, or confidence levels.
- If English localized content is incomplete, the report writer may still render
  evidence tables, but it must not silently machine-translate claims unless the
  workflow explicitly includes a translation/review step.
